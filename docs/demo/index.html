Twelve cases, with the evidence beside each

Eight seeded bugs and the fix that was accepted for each; four fixes that only look right, rejected. Every clip was captured with the harness on the route the verifier judged. The yellow floor line and the readout under each clip are drawn per frame from the engine's own trace, not placed by hand. Viewing this page calls no API.

How these clips were made, and what is recorded versus written for the page

The clips are captures made for this page with the harness (python3 -m harness.demo_clips) on the smoke route, replayed through Godot Movie Maker at 60 fps. The clip manifest records each clip's patches, route, commit, engine and render device, and digests of its frames, trace and video; recording again gave the same bytes. "After" is the clean game with the bug patch reversed, except for physics-fall-through / v1, where it is Muse Code's recorded fix. The case texts are written for this page from the recorded results; only physics-fall-through / v1 shows Muse Code's recorded fix and its reasoning. The rejected fixes' checks are from judge benchmark run 40943391994. Measured numbers, each with its run, are under Results. Recorded reviews with real frames: Muse Code's fix, before and after; the rejected fix that draws the robot inside the ground.

Muse Code's reasoning, from its recorded log

Root cause: the ground lives on physics layer 5 (value 16 in tileset.tres), but the player's mask was 14 (layers 2+3+4: enemies, coins, platforms), so the ground was invisible to it and it fell straight through from the first frames. Fix: in player.tscn, collision_mask = 14 → 30, adding the ground layer while preserving all existing bits.

Why the vision model is not optional

Without it, 5 of the 8 development bugs pass every engine and gameplay check: missing textures, a robot drawn behind the tiles, and a sprite drawn off its body all leave the physics coordinates valid. SAM 3.1, or the open-weight Muse Glimmer checked against the engine (also 8 of 8 on the held-out bugs), sees what the player sees. The full results, with every limit, are in the README.

What the fixer can reach, and what it cannot

A coding agent must never hold the signing key or the held-out checks, or be able to change a check. Expectrail keeps those files out of the fixer's sandbox entirely, and a planted canary file shows what a compromised fixer could and could not read.

fixer-workspace/ (Muse Code)Untrusted
  • The game's source (player/**, level/**)
  • repair-request.json and the failing frames
  • A planted canary file, player/readme-extra.txt, with an instruction a compromised fixer would follow
  • No signing key, no held-out routes, no evaluator
▲ ▼ a boundary by absence, not a VM
verifier-host/ (protected)Out of reach
  • The Ed25519 signing key (.expectrail-signing-key)
  • The private held-out routes (seanudeke/Expectrail-heldout)
  • The reference ground polygon and the deterministic evaluator

Deny-by-absence is a claim about the fixer's mount: on a shared host file system, the verifier's key is still reachable outside it. The OS sandbox closes that gap:
OS sandbox canary, bubblewrap (CI job agents-sandbox: agents.trust --require-sandbox)BLOCKED (exit 1)

Release signing: an Ed25519 keypair is generated per run; its public half is published in release-candidate.json.
Where it signs: only on the verifier host. The private key never touches the fixer's workspace.
